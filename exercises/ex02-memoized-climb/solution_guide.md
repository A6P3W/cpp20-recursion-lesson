## 1. 解法の着眼点・アプローチ

この問題は AtCoder Beginner Contest 129 C - Typical Stairs と同型の、メモ化再帰（動的計画法）の超定番問題です。

$k$ 段目に到達する直前の行動を考えると、以下の2パターンしかありません。

1. $(k - 1)$ 段目から $1$ 段上ってきた
2. $(k - 2)$ 段目から $2$ 段上ってきた

したがって、「$k$ 段目への到達方法の総数 `ways(k)`」は、壊れていなければ **`ways(k - 1) + ways(k - 2)`** になります。
これはフィボナッチ数列と同じ漸化式であり、素朴に再帰すると $O(2^N)$ かかりますが、`memo` 配列でメモ化することで **$O(N)$** で解くことができます。

---

## 2. コードのステップ解説

```cpp
// 1. 範囲外または壊れた段なら到達不可能なので 0 通り
if (k < 0 || broken[k]) {
    return 0LL;
}
```

- `k == 1` のときに `self(self, k - 2)` すなわち `self(self, -1)` が呼ばれますが、先頭で `k < 0` を判定して `0` を返すことで、`k == 1` 用の特別な分岐を書く必要がなくなります。
- また、壊れている段 `broken[k]` に来た場合も即座に `0` を返すことで、「壊れた段を経由するルート」がすべて自動的に $0$ 通りとして扱われます。

```cpp
// 3. すでに計算済みならメモの値を返す
if (memo[k] != -1) {
    return memo[k];
}
```

- 未計算状態を `-1` で表しています。答えは $0$ 以上の余り（$0 \le \text{res} < 10^9+7$）なので、計算結果が `0` 通りの場合でも `memo[k] = 0` として正しくキャッシュされます。

---

## 3. よくある間違い・注意点 (Gotchas)

1. **未計算の初期値を `0` にしてしまう**:
   もし `memo` 配列を `0` で初期化し、`if (memo[k] != 0) return memo[k];` と書いてしまうと、入力例2のように**「到達方法が本当に $0$ 通りの段」**が未計算だと勘違いされ、何回も再計算が発生して **TLE（時間制限超過）** になります。答えとしてあり得る値（`0`）と未計算を表す値（`-1`）は必ず区別してください。
2. **最後に1回だけ `% MOD` を取ろうとしてオーバーフローする**:
   フィボナッチ数列は $N = 93$ で `long long` の最大値を超えます。足し算をするたびに毎回 `(a + b) % MOD` を取るのが鉄則です。
