## 1. 解法の着眼点・アプローチ

制約が $N \le 20$ と小さいことに注目します。
競プロにおいて **$N \le 20$ は「$2^N$ 通りの全探索（$2^{20} \approx 1.05 \times 10^6$）が余裕で間に合う」という強いサイン**です。

各要素 $A_i$ について「選ぶ」「選ばない」の2択を再帰で分岐させつつ、現在選んでいる要素のリスト `chosen` を `push_back` / `pop_back` で管理する**バックトラッキング**で実装します。

---

## 2. コードのステップ解説

```cpp
// 枝刈り (Pruning): すべて正の整数なので、すでに s を超えていたらこれ以上探索しない
if (current_sum > s) {
    return;
}
```

- 制約より $A_i \ge 1$ なので、一度でも `current_sum > s` になると、その先の部分木で合計が減ることはありません。ここで `return` することで無駄な探索を大幅にカットできます。

```cpp
// 分岐1: a[index] を「選ぶ」
chosen.push_back(a[index]);
self(self, index + 1, current_sum + a[index]);
chosen.pop_back(); // バックトラック（状態復元）

// 分岐2: a[index] を「選ばない」
self(self, index + 1, current_sum);
```

- 分岐1の後に `chosen.pop_back()` を実行しているため、分岐2（選ばないルート）に入る時点では `chosen` の中身が「関数に入った直後の状態」に完全に戻っています。

---

## 3. よくある間違い・注意点 (Gotchas)

1. **`index == n` より前に `current_sum == s` で `return` してしまう**:
   今回の問題は $A_i \ge 1$ なので途中で `current_sum == s` になった時点で残りをすべて「選ばない」に確定させても同じですが、もし問題設定が **$A_i \ge 0$（$0$ を含む）** だった場合、途中で `current_sum == s` で打ち切ると「後ろにある $0$ を選ぶパターン」を数え漏らしてしまいます。基本形としては **`index == n`（葉）に到達したときに答えを回収する** のが安全です。
2. **負の数が含まれる問題で `if (current_sum > s) return;` を書いてしまう**:
   もし制約に負の整数（$A_i < 0$）が含まれる場合、一度 $S$ を超えても後から負の数を足して $S$ に戻る可能性があります。枝刈りを入れるときは必ず**「単調性（これ以降増える一方か？）」**を制約で確認しましょう。
