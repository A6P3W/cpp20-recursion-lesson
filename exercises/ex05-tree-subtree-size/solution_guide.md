# 演習5 解答解説: 木の部分木サイズと深さのクエリ（木DFS）

---

## 1. 解法の着眼点・アプローチ

AtCoderのD問題（ABC 138 D - Ki や ABC 202 D / ABC 239 D系）で頻出する**「木上の前計算DFS ＋ クエリ応答」**の王道パターンです。

頂点数 $N \le 2 \times 10^5$、クエリ数 $Q \le 2 \times 10^5$ という制約では、クエリのたびに木を探索すると $O(NQ)$ で時間切れになります。
しかし、根（頂点 $1$）が固定されているため、すべての頂点の「深さ」と「部分木サイズ」はクエリを見る前に**たった1回の木DFS（計算量 $O(N)$）**で完全に求めることができます。

前計算さえ終われば、各クエリは `depth[x]` と `subtree_size[x]` を出力するだけの $O(1)$ となり、全体計算量 **$O(N + Q)$** で高速にAC（正解）できます。

---

## 2. コードのステップ解説

```cpp
// 行きがけ順 (Pre-order): 親の深さ + 1 を子に設定
depth[next_v] = depth[u] + 1;

// 子頂点へ再帰
self(self, next_v, u);

// 帰りがけ順 (Post-order): 子の部分木サイズを親に合算
subtree_size[u] += subtree_size[next_v];
```

- **行きがけ順（`self` の前）**: 親 `u` の深さはすでに確定しているため、子 `next_v` に入る前に `depth[next_v] = depth[u] + 1` と上から下へ値を渡します。
- **帰りがけ順（`self` の後）**: 子 `next_v` から帰ってきた時点では、`subtree_size[next_v]` の計算が完全に終わっています。それを親 `u` の `subtree_size[u]` に足し込むことで、葉から根へとボトムアップに集計が完了します。

---

## 3. よくある間違い・注意点 (Gotchas)

1. **無向辺として両方向に張らず、`tree[u].push_back(v)` だけ書いてしまう**:
   木の入力 $U_i, V_i$ は、「どちらが親（根に近い側）でどちらが子か」が保証されていないことがほとんどです。必ず `tree[u].push_back(v);` と `tree[v].push_back(u);` の**双方向**に辺を張り、DFSの中で `if (next_v == parent) continue;` によって親子関係を決定してください。
2. **`std::endl` を使って $Q = 2 \times 10^5$ 行の出力で TLE する**:
   C++で `std::endl` を使うと、改行のたびに出力バッファのフラッシュ（強制書き出し）が発生し、20万回繰り返すとそれだけで1秒以上かかります。大量の出力を行うクエリ問題では、必ず **`"\n"`** を使いましょう。
