## 1. 解法の着眼点・アプローチ

2次元グリッド上の連結成分を数える典型問題（Flood Fill / 塗りつぶしアルゴリズム）です。

二重ループですべてのマス `(r, c)` を順番に見ていき、「陸地 `#` であり、まだ一度も訪問していないマス」を見つけたときだけ `dfs(r, c)` を起動します。
1回の `dfs(r, c)` によって、そのマスと上下左右でつながっているすべての陸地マスが `visited = true` になるため、同じ島に属する別のマスに二重ループが到達したときには `visited[r][c] == true` となっており、二重にカウントされることはありません。

各マスは高々1回しか訪問されないため、全体の時間計算量は **$O(HW)$** です。$H, W \le 500$（最大 $250,000$ マス）でも数ミリ秒で完了します。

---

## 2. コードのステップ解説

```cpp
auto dfs = [&](auto& self, int r, int c) -> int {
    visited[r][c] = true;
    int area = 1; // 現在のマス自身の分 (1マス)
```

- DFSの戻り値を `void` ではなく `int`（探索した陸地マスの個数）にすることで、グローバルなカウンタ変数を別途用意しなくても、再帰の戻り値だけで美しく島の面積を集計できます。

```cpp
// 1. 範囲外チェック
if (nr < 0 || nr >= h || nc < 0 || nc >= w) continue;
// 2. 海 '.' ならスキップ
if (grid[nr][nc] != '#') continue;
// 3. 訪問済みならスキップ
if (visited[nr][nc]) continue;
```

- 必ず **範囲外チェック → 壁/海チェック → 訪問済みチェック** の順番を守ります。

---

## 3. よくある間違い・注意点 (Gotchas)

1. **`r`（行・縦）と `c`（列・横）を取り違える**:
   グリッド問題で最も多いバグが、`h` と `w`、あるいは `r` と `c` を逆にして `nr >= w` のように書いてしまうミスです。$H = W$ のサンプルケースでは気づけず、提出後の $H \neq W$ のテストケースで RE（範囲外アクセス）や WA になります。「行は `r` (`0 <= r < h`)、列は `c` (`0 <= c < w`)」と変数名を統一しましょう。
2. **`visited[r][c] = true;` を書き忘れる**:
   これを忘れると、隣のマスと永遠に行き来し続けて無限再帰（Stack Overflow）になります。
